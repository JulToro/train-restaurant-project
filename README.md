# Railway Restaurant

Base documental y técnica para validar un restaurante donde trenes a escala transportan alimentos y bebidas hasta las mesas.

## Cómo entender la solución

```text
Discovery → Mercado → Negocio → Producto → Ingeniería → MVP → Piloto
```

- [Discovery](docs/00-discovery/vision.md): visión, problemas, hipótesis y preguntas.
- [Mercado](docs/01-market/market-overview.md): clientes, mercado y referencias.
- [Negocio](docs/02-business-model/business-model-canvas.md): valor, costos, ingresos y riesgos.
- [Producto](docs/03-product/mvp-definition.md): alcance, requisitos y etapas del MVP.
- [Sistema ferroviario](docs/04-railway-system/railway-standard.md): vía, locomotoras, vagones y pruebas.
- `docs/05-14`: electrónica, software, MVP, pruebas, proveedores, restaurante, legal, finanzas, decisiones y lecciones.
- `assets/`, `prototypes/` y `software/`: evidencias y entregables; no decisiones.

## Cómo moverse

1. Empieza por [visión](docs/00-discovery/vision.md) y [supuestos](docs/00-discovery/assumptions.md).
2. Consulta el [Roadmap](ROADMAP.md) para saber qué validar ahora.
3. Sigue los enlaces relativos y evita duplicar información.
4. Usa [templates](templates/) para registrar trabajo nuevo.

## Cómo evolucionar

```text
Hipótesis → Experimento → Evidencia → Decisión → Actualización documental
```

- Distingue `Verified`, `Assumption`, `Estimate`, `To Validate` y `Decision`.
- No avances de MVP sin cumplir su criterio de salida.
- Registra resultados en `docs/07-mvp` y `docs/08-testing`.
- Registra decisiones importantes en `docs/13-decisions`.
- Actualiza hipótesis, riesgos, roadmap y lecciones después de cada ciclo.

El objetivo no es demostrar que la idea funciona, sino descubrirlo antes de realizar inversiones grandes.
