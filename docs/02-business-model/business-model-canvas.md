## Purpose

Describir cómo podría operar el restaurante y aislar opciones futuras.

| Block | Initial restaurant model | Status |
|---|---|---|
| Customer segments | Familias, turistas, celebraciones; parejas | Assumption |
| Value proposition | Comida confiable con ritual de entrega ferroviaria | Assumption |
| Channels | Local, mapas, redes, hoteles, aliados turísticos | Assumption |
| Relationships | Reserva, anfitrión, servicio humano y postvisita | Assumption |
| Revenue streams | Alimentos, bebidas, eventos | Assumption |
| Key resources | Equipo, local, cocina, vía, trenes, control, marca, repuestos | Assumption |
| Key activities | Cocina, despacho, tráfico, limpieza, mantenimiento, seguridad | Assumption |
| Partners | Proveedores food, arrendador, integrador, fabricantes, asegurador | Assumption |
| Cost structure | Personal/insumos/arriendo + CAPEX/OPEX ferroviario | Assumption |

## Future, not MVP

Merchandising avanzado, licencias, instalación para terceros, venta de hardware y plataforma SaaS. Cada uno necesita demanda y capacidades distintas; no financiar el MVP suponiendo estos ingresos.

## Coherence tests

El sistema solo crea valor si aumenta demanda/ticket o reduce fricción más que su costo total. Ver [unit economics](unit-economics.md) y [risks](risks.md).
